# Changelog

All notable changes to **Reqit** are documented here.

The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- Request-chaining VS Code send-path wiring (issue #47): `▶ Send Request` now resolves chain references (`{{name.response.status|headers.<H>|body.$.path}}`, `{{name.request.body.$.path}}`, and bare capture names `{{tok}}`) against the window-session chain store **before** environment substitution; unresolved/malformed chain references block the send with an actionable error instead of shipping a raw `{{...}}`. New pure pipeline `src/core/chain/send.ts` (`prepareChainSend` returns per-substitution secret provenance `resolvedCaptures`/`resolvedSecrets`/`resolvedSecretNames`; `recordChainExchange` records named exchanges + applies `# @capture` directives only for genuinely-received responses — transport failures/cancellations record nothing). Parser now collects `# @capture` lines into `ParsedRequest.captures` (source order, like `@test`; stripped from bodies; capped at 32 per request with a parse diagnostic instead of silent truncation). Secret-flagged captures go out on the wire but are redacted to `[REDACTED]` from every string field of the rendered request echo (url, header values, and body) — redaction provenance is value-equality based, so a direct `{{login.response.body.$.token}}` ref cannot bypass the redaction boundary that a bare `{{tok}}` ref gets; SSE reconnects replay the real wire request while only the redacted view copy reaches the panel. Re-running a named exchange refreshes the captures it owns (response + captures update atomically; cross-exchange name collisions stay errors), capture evaluation JSON-parses each response body at most once per exchange, and capture warnings are bounded (`... and N more`). Scaffold adds `.requests/chain.http` (login → protected call → logout sample, validated end-to-end against the real parser + pipeline in `test/chain.sample.test.ts`). 130 new vitest cases (parser capture collection + limit, pipeline semantics incl. canary-proven redaction, value-equality provenance incl. rejected-secret-capture provenance and owner-scoped refresh, single-parse and failure-records-nothing gates, shared `redactSecretText` longest-first raw+JSON-escaped masking plus fixpoint derived-secret-variant closure (empty expansions, arbitrary-length chained expansions, bounded additions), fail-closed send/copy rejection on injection-provenance overflow with secrets in play, fail-closed exchange refusal at the exhausted secret-provenance quota, fail-closed recorded-body scrubbing (`scrubRecordedBody` keeps `{{name.request.body.$…}}` referenceability and refuses — empty-body record + fail-closed references — when any candidate fails parseability or leaks raw OR JSON-decoded (Unicode-escaped) secret bytes), activate-path wiring on a simulated VS Code host incl. SSE-reconnect wire integrity and secret-scrubbed persisted SSE transcripts, substitution taint closure through plain env values and builtins, chain-aware Copy as cURL with canonical escaped/longest-first masking + explicit reveal + scrubbed validation errors, duplicate-`@name` enforcement, name-length caps across parse/classify/record surfaces with clipped diagnostic echoes, placeholder-candidate-bound scan (empty/abandoned candidates consume the bound) + injection-provenance records, raw-response-view boundary pin, and bounded error/warning surfaces, sample integrity). Advances [#47](https://github.com/rwrife/reqit/issues/47); `Run file` orchestration, codelens chain previews, and CLI `reqit run` integration remain open.
- Request explorer method + name filters: **Reqit: Filter Requests by Method** and **Reqit: Search Requests by Name** (command palette + tree toolbar). Method filter selects HTTP method/GRPC (All methods clears); name search is a bounded (128-char) native input that applies a case-insensitive literal substring match over explicitly parsed request names only (`### name`) across `.http` and `.grpc` requests. Empty clears and Escape preserves. Method/name filters compose with AND, keep folder/file visibility and original send anchors, read active filters after awaited file reads, and ignore stale picker/input completions so older prompts cannot overwrite newer selections. The view title exposes only generic indicators (`Method: ...`, `Name search active`) and never shows/persists the raw search query. Advances [#56](https://github.com/rwrife/reqit/issues/56); URL/body/header search, collection CRUD, path hardening and performance acceptance remain open.

- Request-chaining core (`src/core/chain/`, issue #47): pure resolver for `# @name` + `{{ref}}` request chaining (zod, already a direct dependency, used for capture type validation; no new runtime deps). Adds a bounded JSONPath subset (`src/core/chain/jsonpath.ts`: `$`, `.key`, `['key']`, `[n]` only — wildcards/slices/filters rejected at parse time; max 64 segments; reserved prototype names `__proto__`/`constructor`/`prototype` rejected at parse AND evaluate time even as hostile own keys; strict own-property resolution; `undefined`-valued own properties are misses; array holes serialize as `null`), chain-reference parsing and substitution (`{{name.response.status}}`, `{{name.response.headers.<H>}}` case-insensitive, `{{name.response.body.$.path}}`, `{{name.request.body.$.path}}` — quote-aware placeholder scan so quoted keys may contain `]`/`}`; non-chain refs pass through untouched for env substitution; malformed chain-shaped refs bound to a RECORDED name produce actionable diagnostics instead of passing through; unresolved chain refs stay literal), a per-run in-memory `createChainStore` (records and captures; defensive copies on every getter — capture values deep-cloned for JSON-shaped data; nothing persisted; `recordCaptures`/`getCapture`/`captureNames` with per-run duplicate-name rejection), `# @capture name[: type [secret]] = $.path` parsing with zod type validation (`string | number | boolean`) and a `secret` flag for downstream redaction, per-pass resolution bounds (max 100 acted-on references, recorded JSON bodies parsed once per pass), and `# @name` identifier/uniqueness validation. 63 new vitest cases; documented contract in `docs/chain-grammar.md`. Extension send-path wiring, `Run file` orchestration, codelens previews, and CLI integration remain open on [#47](https://github.com/rwrife/reqit/issues/47).

- SSE webview "Stop stream" button (issue #46): the live streaming-response panel now renders a dedicated Stop control bound to the owning session. The panel markup moved to the pure, unit-tested `src/core/sse/streamView.ts` builder (strict CSP `default-src 'none'` + per-render base64 script nonce validated as canonical base64, full HTML-escaping of untrusted event/URL/header content with fail-closed coercion of non-finite numeric fields, button rendered only while a session is live). The inline shim latches one-shot and disables itself BEFORE posting its fixed message (`{type:"reqit-sse-stop",token:"<per-session>"}`, the token an 8–64 char base64url secret generated per session); the host validates the message structurally (`isSseStopMessage` — plain-prototype object, exactly two own keys incl. symbols, matching the session token via constant-time compare, prototype-forgery safe) and routes it to the panel-ownership token's session `SseStreamHandle.abort()` (id-scoped, idempotent, superseded sessions cannot paint or act and their message listener is disposed synchronously on ownership handoff, so a queued click from an old session can never abort the new owner's stream), so a click can only stop the displayed live stream. Transcript capture goes through the `pickSseTranscriptRecord` allowlist boundary so request-adjacent auth material is structurally excluded from saved `.sse.jsonl` files. The shared response panel recreates itself between scripts-disabled (plain/gRPC views) and scripts-enabled (SSE) modes so scripts are enabled only for the live-stream view, every terminal transport path disposes the message channel and panel ownership (before any awaited transcript prompt), and the stale README note claiming closing the panel leaks the socket was corrected. 32 `streamView` + 3 transcript secret-safety vitest cases (button presence/scoping, CSP/nonce lockdown incl. non-canonical base64 rejection, single-layer XSS escaping of hostile payloads and non-finite numbers, token-bound message-validation rejection matrix, shim at-most-once ordering, non-vacuous end-to-end secret-absence proof). Advances [#46](https://github.com/rwrife/reqit/issues/46).

- SSE stop/cancellation control: pure `SseStreamRegistry` + `closeOnAbort` (`src/core/sse/streamControl.ts`) track live SSE sessions; the new `Reqit: Stop SSE Stream` command aborts every live session, the transport races its next-chunk wait against the stop signal (stalled streams return `aborted` promptly; late chunks can never dispatch late events), in-flight/reconnect sockets are destroyed on stop, and live sessions are aborted on deactivate. Hardened across the full lifecycle: reconnect backoff sleeps and in-flight `connect()` calls are raced against the stop signal (a stop during backoff or during a hanging reconnect request resolves immediately and never surfaces the late result as an error), reconnect HTTP requests bind to the stop signal so pending sockets cancel instead of orphaning, the driver restores `for await` iterator-close semantics (every early stop — abort, caps, until-match, callback error — releases the input generator and body), and transport failure text shown in the webview/notifications is sanitized (URL userinfo/query/fragment and secret assignments stripped, length-bounded). 25 new vitest cases incl. end-to-end local-server stop/reconnect tests. Advances [#46](https://github.com/rwrife/reqit/issues/46).

- gRPC message framing (`src/core/grpcFrame.ts`) and status-code taxonomy (`src/core/grpcError.ts`): pure, transport-free building blocks for the reflection-backed runner. `encodeFrame`/`decodeFrame`/`decodeFrames` implement the 5-byte length-prefixed HTTP/2 gRPC wire format (compressed-flag aware, multi-frame safe); `reportForStatus` and `reflectionUnsupportedReport` map every canonical `grpc-status` code plus the synthetic reflection-unsupported case to actionable, plain-English hints (UNAVAILABLE = check host/TLS, UNAUTHENTICATED = check @auth profile / mTLS, UNIMPLEMENTED = wrong service/method, etc.). 25 vitest cases; zero new runtime dependencies. Prep for [#24](https://github.com/rwrife/reqit/issues/24).
- Release preflight script (`npm run preflight`): validates `package.json` (semver + non-placeholder version, `publisher`, `icon`, `license: MIT`, `engines.vscode`, `activationEvents`), `CHANGELOG.md` (matching `## [<version>]` section), `README.md` (Features / Install / Quick start), `media/icon.png` (real 128×128 PNG), and re-scans `src/` for known telemetry SDK imports. Rule set is pure and lives in `src/core/releasePreflight.ts` with 24 vitest cases. CLI supports `--json` for CI. Wraps up the last automatable piece of M7 marketplace release ([#7](https://github.com/rwrife/reqit/issues/7)); exit 0 = ready to tag, exit 1 = fix stuff, exit 2 = script self-broke. Companion doc: [`RELEASING.md`](./RELEASING.md).
- gRPC preflight report: the `.grpc` preview panel now shows a **Preflight** banner above the request details, reporting whether the target `Service/Method` resolves against the reflection descriptors (once available), flagging unknown services/methods with actionable hints, warning on reserved gRPC metadata headers (`te`, `grpc-timeout`, `-bin` suffixes, etc.), and blocking streaming methods (unary-only in v1). Ships as pure `src/core/grpcPreflight.ts` with 15 vitest cases; the extension layer is a thin renderer. Prep work for [#24](https://github.com/rwrife/reqit/issues/24) — no live wire dispatch yet, but the preflight will feed the reflection-backed runner once it lands.
- gRPC codelens + preview: `.grpc` files now get a `▶ Send Request` codelens (and the Requests tree entries invoke it) that opens the response panel with the parsed target, auth profile, metadata, and body. Live wire dispatch (server-reflection + mTLS) is still tracked under [#24](https://github.com/rwrife/reqit/issues/24); this slice unblocks the UX so users can validate `.grpc` files end-to-end today.
- GraphQL request support in `.http` files: trigger with `# @graphql` or `X-Request-Kind: graphql`; auto-builds `{ query, variables, operationName }`, runs `{{var}}` substitution across both the document and the variables JSON, and pretty-prints `data` / `errors` separately in the response viewer ([#23](https://github.com/rwrife/reqit/issues/23)).
- README: Features / Install / Quick start / Auth examples sections — marketplace-prep polish for [#7](https://github.com/rwrife/reqit/issues/7).
- Marketplace metadata: `keywords`, `galleryBanner`, `qna`, `pricing`, `homepage`, `bugs`, `author`, and `capabilities` declarations in `package.json`.
- `CHANGELOG.md` (this file) — VS Code Marketplace surfaces it on the extension page.
- Marketplace icon at `media/icon.png` (128×128) generated by `scripts/generate-icon.mjs` (no native image deps). Regenerate via `npm run icon`.

## [0.0.1] - Pre-release
